# P’s CUBE：止められない取り込み方の検討（2026-10-01）

## 決定（利用者の選択、2026-10-01）

- **実装した**：人間確認の画面を見分ける（hCaptchaの窓・注意書き「ロボットでないこと」「約款に同意して」）。確認画面ではONのまま待つ。
  確認画面でもないのに対象のページでデータが出ない状態が**5回以上・1分以上**続いたら、止められたとみなして自動取り込みをOFFにする
  （再開は手動）。PC `AutoPilot`、Android `PscubeAutoGuard`、判定は共用の `autoPageState`（`challenge`／`missing`）。
- **却下**：案1（台別ページを7日に1回）。利用者は毎日データを取るため。
- **今回は入れない**：案2（1時間の上限）、案4（一覧だけ）、案5は運用（1日1回）で既にそうしている。
- Cookie：Androidはサードパーティを受け付け、PCはシークレットモードをやめて `data/pscube-webview` に保存（実装済み）。アプリ内でCookieを消す処理は無い（点検済み）。

以下は検討時の記録。

利用者の依頼：「蹴られないような仕組みを検討しておいて」。

**前提（作らないもの）**：接続元（IP）やブラウザの種類（ユーザーエージェント）の書き換え、人間確認（hCaptcha）の
自動突破、人間らしく見せるための操作の細工。これらはサイトの制限をすり抜ける行為で、約款の禁止事項
「本サイト運営のシステムに負担をかけ、または不正にアクセスすること」にも触れうる。接続元ごと長く止められる危険もある。
方針は**サイトにかける負担（開くページの数と速さ）を減らし、止められる理由を作らない**こと。

## これまでに分かったこと（事実）

- 台別ページ（`nc-v06-001.php`）で毎回人間確認が出たのは、アプリがCookieを保存・送信できていなかったため
  （Androidはサードパーティ拒否、PCはシークレットモード）。直したら毎回は出なくなった。
- Androidで自動取り込み（当時の間隔3.5秒）を放置したら、人間確認なしで**データが表示されなくなった**
  （止められた可能性。サイト側の基準・止める時間はわからない）。
- 機種一覧・全台一覧では人間確認は出ていない。台別ページは1台ごとに1ページで、全部だと約2,000ページになる。
- 台別ページ1回で**7日分**（今日〜6日前）の数値とグラフが取れる。
- 当たり0回の台は台別ページを開かない（2026-10-01 実装済み）。間隔はP’s CUBEだけ5〜60秒・初期10秒（実装済み）。

## 案（効果の大きい順）

### 1. 台別ページは「1台につき7日に1回」にする（おすすめ）

台別ページは1回で7日分が取れるので、毎日開く必要はない。全台一覧（約61ページ）は毎日取り、その日の数値と一覧の
グラフはそこで得る。台別ページは、前回その台の7日分を取ってから6日以上たった台だけを開く。
**台別ページの数は毎日の約2,000から、平均で1日約300に減る**（約7分の1。当たり0回の台を除けばさらに減る）。
グラフは「一覧の粗いグラフ（毎日）＋台別の細かいグラフ（7日ごとにまとめて）」になる。

### 2. 1時間あたりの上限と休憩

自動取り込みで開くページを「1時間に◯ページまで」にし、上限に達したら自動で休憩して、時間が来たら続ける。
数値はサイトの基準がわからないので、控えめな値（例：1時間120ページ＝平均30秒に1ページ）から始め、止められなければ
少しずつ上げる。

### 3. 止められた気配があったら自動で止まる（間をあける）

対象のページなのにデータが表示されない、が続いたら自動取り込みをOFFにし、「サイトがデータを表示しなくなりました。
時間を空けてください」と出す。放置しても叩き続けない。再開は利用者が手動でONにする（自動の再開はしない）。

### 4. 毎日は一覧だけ、台別は見たい機種だけ

「台別7日分は取らない」の切り替え。または、機種タイプがノーマル（ジャグラー・ハナハナ）など、採点・候補で
よく使う機種だけ台別ページを取る。

### 5. 取り込む時間帯

1日1回、営業終了後（数値が確定した後）にまとめて取る。営業中の何度もの取り直しをしない。

## 記録（判断の材料を残す）

どの時刻に何ページ開いたか、止められた（データが出なくなった）時刻を、端末・PCの中に記録する。
安全な速さの目安は推測できないため（わからない）、実際の記録から決める。記録はサイトには送らない。

## おすすめの組み合わせ

**1＋3（＋必要なら2）**。1で量そのものを大きく減らし、3で放置しても叩き続けないようにする。
2は1・3でも止められるときに足す。いずれも未実装。利用者の選択を待つ。

## 2026-10-02：アプリだけ止められたときの「サイトの記録を消してやり直す」（実装済み）

- 経過：Android版で数十台を自動取り込みしたあと、データが表示されなくなった。約7時間あけても同じ。
  同じスマホのChromeでは開けた（利用者の確認）。回線（IPアドレス）ではなく、アプリのブラウザに残る
  Cookie・保存データの単位で止められていると考えられる（推測。サイトが何を見ているかはわからない）。
- 対応：Android（右上のクッキーのボタン）とPC（取り込みカードの一番下のボタン）に「サイトの記録を消して
  やり直す」。確認のあと、自動取り込みをOFFにし、Cookie（AndroidはアプリのWebView全体、PCはP’s CUBE専用の
  `data/pscube-webview`）とページの保存データ（localStorage・sessionStorage・IndexedDB・キャッシュ）を消して、
  最初のページを開き直す。取り込んだ記録（`pscube.sqlite3` / アプリのP’s CUBEの記録）は消さない。
  保存中は断る。人間確認・同意が出たら利用者が手で操作する（自動では触れない）。
- 止められた気配で自動停止したときの案内文に、このボタンを書き添えた。
- Androidの注意：CookieはアプリのWebView全体で共有のため、メルヘンの取り込み画面でも次回に同意・確認が出ることがある。
- やらないこと：回線の切り替え・ブラウザの偽装・人間確認の自動突破（サイトの防御をかいくぐるため）。
- 消しても再び止められるなら、量を減らす（上の4「毎日は一覧だけ」）を検討する。全台一覧のグラフは17点、
  台別ページは15〜17点で細かさはほぼ同じ（2026-10-02 PCの記録で確認）。ただし縦の目盛りが違う可能性があり、
  採点への影響を先に確かめる。
