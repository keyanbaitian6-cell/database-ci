# P’s CUBE 自動取り込み（PC版・Android版）

決定日：2026-10-01（利用者の指示：「P’s CUBEの取り込みにも、昨日追加した自動取り込み機能をPC版・Android版ともに」。
仕様は利用者の選択どおりメルヘンと同じ）。メルヘンの自動取り込み（PC：`auto_capture.py`・`browser_import.py`、
Android：`auto_capture_state.dart`・`web_import_page.dart`・`AutoCaptureService.kt`）と同じ部品・同じ決まりを使う。

## 決まり（メルヘンと同じ）

- 「自動取り込み：OFF／ON」ボタン。**起動時は必ずOFF**。ON状態は保存しない。
- **間隔はP’s CUBEだけ15〜25秒のランダム**（2026-10-05 利用者指定、PC・Android共通）。待機を設定するたびに100マイクロ秒刻みの100,001通りから抽選する。手動の間隔変更はできず、画面は今回の待機時間を表示する。メルヘンは0.1〜4.5秒・初期3.5秒のまま。接続元やブラウザの種類を書き換えて制限をすり抜ける処理は作らない。
- **人間確認（「私は人間です」）・利用規約の同意・読み込み中の画面では、ONのまま待つ。自動では押さない。** 利用者が操作して
  対象のページが表示されたら、そこから続ける。サイトのボタンやリンクは押さない（読むだけ）。
- 確認画面ではない（hCaptchaや注意書きが無い）のに対象のページでデータが出ない状態が5回以上・1分以上続いたら、止められたとみなして**自動でOFF**（再開は手動。`PSCUBE_ACCESS_PLAN.md`）。
- ONの間は手動の「未取得を取り込む」は押せない。OFFは新しい取り込みを止める（始まった保存は完了まで待つ）。
- PC版は時間をPython側で数える（窓を最小化しても遅れない）。Android版はメルヘンと同じ常駐通知で、ほかのアプリの裏でも続く。

## P’s CUBEの部分

- **ページの判定**（`web/pscube/data.mjs` の `autoPageState`、PC・Android共用の `assets/pscube_auto_probe.js` に生成）：
  機種一覧（`cd_ps=2` で機種の一覧がある）・全台一覧（台の一覧と選ばれた日付がある）・台別7日分（日付のhashと7日分の表がある）の
  どれかで表示がそろっていれば「取り込める」。それ以外（最初のページ・確認画面・対象外）は理由を出して待つ。
- 取り込めるときは、手動の「未取得を取り込む」と**同じ処理**（全台を表示→読み取り→検証→保存→次の未取得ページへ移動）。
  保存・バックアップ・ドライブ同期も手動と同じ。
- 台別7日分のページでは、サイト自身の `nc-m06-003.php` から連続グラフの元数値を取得する。
  新台・入れ替え後に過去の列が全空欄でグラフもない場合は、その日を省略し、表示された日だけ保存する。
  共通JSの `missing_history_days` と保存する日を合わせて直近7日になることをPC・Androidで確認する。
  本日の空欄、一部だけ欠けた過去列、数字が不正な列、数字が空なのにグラフがある列は保存しない。
  空欄を0に置き換えず、過去の記録も削除しない。取り込み済みの印は選択日に付け、空の過去日で巡回を止めない。
  入れ替え日は最新の機種一覧から取り込む。旧機種・旧台番号の履歴を新しい機種や台番号へ自動移動しない。
  取り込み日を指定して開いた全台一覧に、その日の日付タブが無い機種（入れ替えで入った新台。サイトは最新のタブを選ぶ）は、
  その機種のその日を「サイトに記録なし」として `state` の `absent_table_days` に覚え、保存せずに次へ進む（その日の未取得から外す）。
  指定日がタブより新しい（早朝でタブがまだ出ていない）ときは飛ばさない（2026-10-19、入れ替えの日に前日を取り込むと止まった）。
  自動取り込みは表示中の日が取り込み日と違うページでは待つが、全台一覧で、判定が返す日付タブ（`days`）に取り込み日が無く、
  取り込み日がタブの最新より前で、選ばれているタブがその中にあるときだけは読み取りへ進め、保存側が読み取り結果の日付タブで
  確かめて飛ばす（2026-10-22。以前は読み取りの前に待ち続け、保存側の飛ばす処理まで届かなかった）。タブが読めない・取り込み日の
  タブがある・取り込み日がタブより新しい・人間確認や読み込み中・台別ページの日付違いは、今までどおり待つ。
  規則はPC `day_tab_absent`・Android `pscubeDayTabAbsent` で同じ（自動の判断と保存側の両方が使う）。
  台別ページへのリンクが無い台は、全台一覧の住所で代用せず「N番台の台別ページへのリンクがありません」で止める。
  利用者の確認（2026-10-19）：過去の日の全台一覧にも、その日ではなく今の台数・台が出る（前の日の台数は出ない）。
  前日のデータが無い機種は撤去されたと読む（撤去機種の最終日は取り込まない）。
  増台の翌日に前日を取り込むと、過去の日の全台一覧にも今の台が並び、増えた台はその日の数値もリンクも無いと考えられる
  （実際の画面は未確認。利用者「止まる可能性があるなら今のうちに」2026-10-19）。共通JSはリンクも数値もすべて空の台を
  `missing_racks` として返し、0で埋めない。PC・Androidは、過去の日（日付タブの最新より前）に限り、保存した台＋その台
  ＝設置台数で受け付け、`state` の `absent_table_racks` に覚えて未取得の数え方に足す。全部そろった一覧を取り直したら消す。
  その機種・その日の全台一覧を正しく保存できたら（数値なしの台を含む過去の日の一覧も）、同じトランザクションで
  `absent_table_days` のその組み合わせだけを外し、未取得に戻す（2026-10-22。以前は外さず、機種ごと除外され続けた）。
  拒否した一覧・保存に失敗した一覧では、記録も両方の印も変えない。
  今動いている日、数値のある台が1台も無いページ、数値があるのにリンクが無い台は、今までどおり理由を出して止める。
  各日の終点と始点の差を `net_medals` に保存する。MYとは別の値で、元数値のある日だけ付ける。
  通信失敗・拒否や元数値の形式不一致でも、台別の数値・グラフは今までどおり保存して次へ進み、差枚は空欄のまま（0にしない）
  「差枚は未取得」と表示する（利用者の選択、2026-10-03。巡回を止めないため）。翌日以降にその台を開けば過去6日分の差枚も埋まる。
  手動でその台別ページを開いて「未取得を取り込む」を押しても再取り込みできる。
  当たり0回の台は従来どおり台別ページを巡回しないため、この経路では差枚を取得しない。
- 同じページは2回保存しない（一覧はスクロールのhashを無視、台別は日付のhashで区別）。
- 同じページで3回続けて保存できなければ、そのページは待機（手動で確認するか、OFF→ONでやり直し）。
- 未取得が無くなったら（次のページが無い）、**自動でOFF**にして「すべて取り込みました」と出す（メルヘンとの違い：P’s CUBEは
  終わりがはっきりしているため）。

## 実装

- PC：`pscube_import.py` の `AutoPilot`（判断）と `overlay_script`（右下のカード：手動の取り込み・ON/OFF・間隔・状態）。
  `build_windows.ps1` は判定スクリプトも同梱する。
- Android：`pscube_import_page.dart`（ボタン・間隔・状態・常駐通知）、`pscube_auto.dart`（判断の規則）。

## 限界

- 実サイト（人間確認・同意を含む）での連続運転は、利用者の操作が必要なため未確認。確認した範囲は `AI_COLLABORATION.md` に書く。
- 間隔を短くすると、サイトの人間確認が出やすくなる可能性がある（未確認・わからない）。サイトの利用規約で自動の閲覧が
  制限されているかは確認していない（わからない）。
