# PC版 自動取り込みの完成・配布記録（2026-09-30）

利用者の今回の明示的な依頼を優先し、従来文書の「自動取り込みを実装しない」方針を、このPC版の任意ON機能について更新した。人間確認・CAPTCHA・利用規約同意を自動で操作する処理は追加していない。

## 起動と操作

`database/start.cmd` から起動し、「ブラウザで取り込む」→「ブラウザを開く」。開始する店舗・日付を選び、必要な確認・同意は自分で操作する。

大きな「自動取り込み：OFF」ボタンを押すと緑色のONになり、もう一度押すと灰色のOFFになる。間隔はOFF中に0.1〜4.5秒、0.1秒刻みで変更できる。起動時は必ずOFF・3.5秒。小さな窓ではカード内をスクロールでき、停止ボタンは上部に配置した。

ページ遷移・機種一覧・読み込み・確認画面・エラーでONを解除しない。条件が整うまで待機する。OFFは新しい自動取り込みと未確定の自動移動を止める。すでに開始した保存は完了まで待つ。取り込みブラウザの終了時に停止し、ON状態を次回へ保存しない。

- `browser_import.py`：既存の抽出・保存処理を使用。機種選択中の重複起動を抑止し、非同期処理の完了時にON状態と世代を再確認。OFF後の読み直しで旧機種移動が復活する経路も無効化。保存プロセスは手動と自動の競合も含めて1つに制限。完了通知ファイルはブラウザごとに分離。
- `auto_capture.py`：Pythonタイマー、ON/OFF状態、試行間隔、同一内容の重複保存防止、確認・読み込み待ち、ボタンとカードのサイズ調整。

- PC全体：`python -m unittest discover -s tests` **147件成功**。上記26件を含む。以前の139件に18件を足す二重計上はしていない。ログ：`build/auto-capture-unit-tests.log`。
- `tests/smoke_auto_capture.py`：実際のWindows/WebView2とlocalhostのダミーページ、一時DBで確認。JavaScriptは構文だけでなく実行した。旧移動と自動タイマーの競合、非同期機種選択中のOFF、OFF後の再読み込み、確認ダイアログでON待機→解除後の再開を確認。
- 同テスト：Windowsの `WindowState=Minimized` のまま、機種一覧→表保存→グラフ保存→機種一覧に戻るまで成功。別の最前面テスト窓が取り込み窓全体を覆う状態でも表保存と移動に成功。360×300と573×495の窓、既存倍率1.6で停止ボタンの全体が表示領域内にあることを座標で確認。ログ：`build/auto-capture-webview-test.log`。この実画面試験は147件とは別枠。
