# database（試作版）

メルヘンワールド長町南店とスーパーメルヘンワールド幸町の1000円46枚スロットだけを対象とする、個人用のローカルツールです。
`start.cmd` をダブルクリックして起動します。入力方法はAndroid版と同じく、アプリ内ブラウザでの直接取り込みだけです。PC版のメイン画面は「取り込み」「結果を見る」「バラエティ🌈」「バックアップ・同期」の4タブです。

「バラエティ🌈」→「本日（取り込み前も🌈）」では、当日の数値を取り込む前でも印を付け外しできます。直近の台一覧の参照日を確認し、表の本日の「＋」または一覧の🌈列を押してください。印はその場でPCへ保存され、後から当日のデータを取り込んでも残ります。未取得の数値は作りません。未取り込み日の印はPCバックアップでも復元でき、Webへは当日の数値取り込み後に既存のGoogle同期で反映します。

起動時には未表示の🌈表を作らず、取り込み済みで更新時刻の変わらないバックアップの内容を読み直しません。日別原本・閲覧パーツはバックアップの自動検索から除外します。新しいバックアップがある場合は、従来どおり自動取り込み・レポート更新が行われるため、その処理には時間がかかります。取り込みに失敗したファイルは「取り込み済み」として覚えず、次の起動でやり直します。前回取り込んだファイルより古いバックアップは、前回のファイルが消えていても自動では読み直しません（手動の「同期フォルダの最新を読み込む」は従来どおり）。
（2026-10-14 レビュー）保存のたびに古い観測記録を消す処理が索引なしで全件を読んでいたため、`observations` に索引を追加しました。通常DBの専用コピーで、新しいAndroidバックアップ551行の取り込み本体が約21.5秒→約1.3秒。取り込み後のレポート更新（約8秒）とバックアップ書き出し（約3秒）は残っており、その間は画面が止まります。

PC版は最新の `main` にある `database/start.cmd` から起動します。初回は `database/setup_python.cmd` を一度実行して、固定版の依存を入れた専用Python `.venv` を用意してください。起動とビルド前チェックはこの専用環境を優先し、別のシステムPythonを自動では選びません。まだ `.venv` を作っていない既存環境では `.runtime` を引き継ぎます。取り込みブラウザも同じPythonでこのフォルダのソースを起動します。記録・設定は従来どおりこのフォルダの `data` に保存されます。別の場所から切り替えるときは、既存の `data` を引き継いでから起動してください。

## Windows版EXE

`bin\database\database.exe` を起動すると、PythonのインストールなしでPC版を使えます。`bin` フォルダは、`database` フォルダと `database-browser` フォルダを含めたまま置いてください。メイン画面の「ブラウザで取り込む」を押すと、補助プログラム `bin\database-browser\database-browser.exe` が自動で起動します。

この配布物は、プロジェクト内の既存の `database\data` と `database\reports` を優先して使います。したがって、現在の記録を引き継ぐ場合はEXEだけを取り出さず、リポジトリの `database` フォルダ内に `bin` を置いた状態で起動してください。EXEのビルド時に既存データをコピーしたり初期化したりはしません。実サイトの規約画面や実ページでの取り込み動作は、自動ビルド検査の対象外です。

## ブラウザで直接取り込む

1. メイン画面の「ブラウザで取り込む」から「ブラウザを開く」を押すと、別ウィンドウで対象2店舗専用のブラウザが開きます。
2. ブラウザ内で開始する店舗・機種・日付は自分で選びます。利用規約への同意が出た場合もご自身で操作してください。画面のカードには、もう一方の店舗を開くボタンもあります（ドラッグで好きな位置に動かせます）。ブラウザの位置・大きさと、カードの位置・大きさは `data/browser_layout.json` に保存され、次に開くときも同じ配置になります。
3. 機種別の一覧ページで「この画面を取り込む」を押すと、今表示されているHTMLの表を直接読み取り、その場で保存します（確認画面はありません。スクリーンショットもOCRも使いません）。台番号・BB・RB・総回転数・前日最終スタート・最大持玉を取得し、URLの`target_date`があればそれを保存日として最優先します。台番号が重複していたら、勝手に削除・統合せずエラーで知らせて保存を止めます。未稼働台や数値が同じ連続台も、別台としてそのまま保存します。幸町店の一覧には最大持玉の列自体が無いため、その場合は最大持玉なしで保存し、個別グラフページ側の表示から後で埋まります。
4. 個別台のグラフページで「この画面を取り込む」を押すと、SVGの線とゼロ線からグラフを保存します。機種名や一覧の数値は、同じ店舗・日付・台番号の保存済み一覧を引き継ぎます。一覧未取得や読み取りエラーの場合は保存せず、エラー画面を表示します。人間確認・CAPTCHA・利用規約への同意は自動操作しません。
5. 保存後は、既存の次の未取り込み台・機種へ進む処理を使います。「自動取り込み」がOFFなら、移動先での新しい取り込みはボタンを押して開始します。
6. 保存した縮小グラフと4点座標はSQLiteに記録されます。
   自動バックアップ（日付入りの控えと、同期フォルダの `database-backup-auto.json`、直近7日分の `database-backup-recent.json`）は、保存のたびではなく**内部ブラウザを閉じたときに1回**取ります（記録が増えても取り込み中に待たされないように）。閉じたときに確認画面が開いていれば、その保存が終わってから取ります。
   **Androidでふだん読み込むのは `database-backup-recent.json`**（最新の記録日から7日分。全期間の `database-backup-auto.json` は127MBほどあり読み込みに約2分かかるため。2026-10-18）。7日より前の日を直したとき（機種名の直しなど）や、しばらく読み込まなかったときは、全期間の `database-backup-auto.json` を読み込む。削除の印はどちらのファイルにも全期間分が入る。PC版は自分で書き出したこの2つを読み込み直さない。
7. メイン画面の「選んだ機種の結果を開く」「過去の記録を見る」で確認します。

対象は長町南店・幸町店の1000円46枚スロット（`kind_code=21`）だけです。対象外のURLへは遷移できないよう自動で戻し、対象外ページからのデータ取り込みも拒否します。同意操作の自動化、IP変更、アクセス制限の回避はしません。2026-09-30の利用者の明示的な依頼により、PC版は下記の任意ONによる自動取り込みに対応しました。外部サービスへ画像・台データを送信しません。

## メルヘンのCookie・再読み込み

PC版は `data/meruhen-webview` にCookie・サイトの保存状態を保持します。P’s CUBEの `data/pscube-webview` と別の場所です。
Android版はブラウザ設定とサードパーティCookieの許可を完了してから初回ページを開きます。
認証・同意は、サイトに表示された画面で手動操作してください。Cookieが保持されても、期限切れやサイトの判定によって再確認が必要な場合があります。

PC版のカードにある「再読み込み（Cookie・記録は保持）」、Android版の上部にある再読み込みボタンは、Cookieや取得済み記録を消さずにページを開き直します。
自動取り込みはOFFになります。PC版で確認・保存の画面が開いているとき、Android版で取り込み処理中のときは、完了後に押してください。
PCのDNSなどの通信エラー画面にも「もう一度開く」があります。HTTP拒否の本文は認証操作が含まれる可能性があるため、そのまま表示します（自動取り込みはOFF）。DNSやHTTP 403がCookie変更だけで解消する保証はありません。

## 自動取り込み（PC版）

- 起動時は必ず **OFF（灰色）**、間隔は **3.5秒**。大きな「自動取り込み：OFF」ボタンを押すと **ON（緑色）**、もう一度押すと停止します。
- OFF中にスライダーで **0.1〜4.5秒、0.1秒刻み**に変更できます。設定値は次の試行までの待ち時間です。ページの読み込みや保存が終わるまでは待つため、保存が必ずその周期で完了する意味ではありません。
- 既存の「この画面を取り込む」と同じ表・グラフの抽出と保存処理を呼びます。機種一覧でもONを保持し、既存の次の対象を選ぶ処理を使います。
- 次の機種の行を押しても画面が変わらないときは、Python側タイマーで再確認し、保存済みの対象日を保った機種別一覧URLへ進みます。OFFを押した後はこの再試行も行いません。
- 最小化中・別ウィンドウの裏でもPython側のタイマーが動きます。読み込み中、確認画面、CAPTCHA、同意画面ではONのまま待ちます。主ページのDNS・通信失敗とHTTP 400以上ではOFFにして再試行を待ちます。操作が必要な画面は利用者が手動で処理してください。
- OFF後は新しい自動取り込みと、未確定の自動移動を開始しません。すでに始まった保存は完了まで待ちます。同時に複数の保存プロセスは起動しません。
- ON中は手動取り込み・取り消しボタンを無効にします。ブラウザを閉じると自動取り込みは終了し、次回はOFFです。小さな窓ではカードをスクロールできます。
- ダミーページ・一時DBでの検証と配布履歴は [AUTO_CAPTURE_RELEASE_20260930.md](AUTO_CAPTURE_RELEASE_20260930.md) を参照してください。実サイトに対する自動操作は検証していません。
- 2機種連続の停止修正と配布履歴は [AUTO_CAPTURE_FIX_20261001.md](AUTO_CAPTURE_FIX_20261001.md) を参照してください。
- 保存中の再読み込みに関する追加修正と最新配布履歴は [AUTO_CAPTURE_REVIEW_20261001.md](AUTO_CAPTURE_REVIEW_20261001.md) を参照してください。

## 消した記録を戻す

「台記録を削除」で消した台は、消す前に日付入りバックアップと同じ場所（同期フォルダを設定していればその中、無ければ `data`）の `backups/deleted/database-deleted-日時.json` として7日間残ります。戻したいときは「バックアップを読み込む」でこのファイルを選んでください（今の記録がある台は上書きしません）。

## Android版とバックアップを共有する

「バックアップ（Google Driveなどで共有）」から、保存データをJSONファイルとして書き出し・読み込みできます。ClaudeやこのPCアプリ自体はGoogle Driveを直接操作しません。Google Drive for Desktopの同期フォルダや、ブラウザでのDriveへの手動アップロードなど、ご自身の操作でファイルを共有してください。Android版も同じ形式のファイルを「バックアップを共有（書き出し）」「バックアップを読み込む」から扱えます（Android側はファイル選択画面からGoogle Drive上のファイルを直接選べるため、Android側にもGoogle API連携は不要です）。

1. 「バックアップを書き出す」の隣で店舗・日付を選べます（それぞれ「すべての店舗」「すべての日付」も選べます）。絞り込むと、その範囲の全機種だけを書き出します。
2. そのファイルをAndroid版で「バックアップを読み込む」から選ぶと取り込めます（逆にAndroid版で書き出したファイルをPC版で読み込むこともできます。Android版も書き出し時に店舗・日付を選べます）。
3. 取り込み時、同じ店舗・日付・機種・台番号で数値（総回転数・BB・RB・最大持玉）が食い違う記録は自動で上書きしません。新規記録とグラフのみの追加は自動反映し、数値が食い違う記録は確認画面に一覧表示するので、必要なものだけチェックして反映します。
4. PC版のSelenium取得由来の生グラフ（`graph`）はAndroid版のスキーマにない形式のため、バックアップ経由では数値のみ引き継がれ、グラフ画像は引き継がれません（`graph_measurement`形式のグラフは双方向で引き継がれます）。

- メイン画面の店舗・日付・機種名は自由入力ではなく、保存済みの組み合わせだけを選べるプルダウンです（「選んだ機種の結果を開く」「台記録を削除」で使用）。
- 幸町店の一覧ページには最大持玉の列が無いため、`max_hold`が無いまま保存されることがあります（個別グラフページ側の表示から後で埋まります）。結果表・過去の記録では「—」で表示し、採点は最大持玉の比較データ不足として扱います。
- 現行の配点ではゼロ線・最高点・終点を採点に使い、最低点はグラフ形状の記録として保持。
- 表示G、BB、RB、最大持玉、グラフの描画座標、出典URL/ページをSQLiteに日付別保存。
- 再取得時も過去日を保持し、取得履歴も別表に追加。数値が同じなら既存グラフを保持し、数値が訂正された場合は対応しない古いグラフを採点から外します。

- 店舗・日付・機種で絞り込める過去記録画面を `reports/database-history.html` に更新。台番号を押すと、保存済みのスランプグラフ（実画像、または元画像がない場合は4点から復元した概略グラフ）をその場で確認できます。

## 採点（2026-09-25-v10）

[採点仕様書](../SCORING_POLICY.md)を正とします。
当たり頻度60点、最大持玉20点、終点10点、維持10点。回転数は加点せず、比較対象の選定と縮約に使います。
同店・同機種・過去30日の回転数が近い台で比較し、当日・未来は使いません。
当日500G以下の台は採点しません（「保留」表示）。
少数の比較は中立へ縮約し（v9で、3つの薄さの目安を掛け算から相乗平均に変更）、欠測項目は中立補完した暫定点・評価可能配点・欠測幅を表示します。
最大持玉は、枚数そのものによる点（19,000枚のコンプリート上限で満点）が順位による点を上回ればそちらを使います。引き上げにだけ使い、下げることはありません。
これは実績の独自評価です。設定確率・明日の勝率・期待収支はわかりません。
台番号別の当たり頻度の過去傾向に基づく「翌日候補（仮）」を、同じ機種で3日以上の履歴があり、候補化できる台が4台以上ある場合だけ表示します。採点とは独立し、翌日の優位性は検証中です。
保存済み記録は再取得不要。新しい結果・履歴画面を開くと再計算します。旧HTMLを直接開くと旧点数のままです。

検証：`python -m unittest discover -s tests -q`、読み取り専用全件監査：`python audit_scoring.py`。
監査結果は `reports/scoring-v8-audit/` に保存されます。

## 取得方法と制限

ブラウザ直接取り込みは、`pywebview`（WindowsではWebView2）で対象2店舗を表示し、現在のHTML表またはSVGグラフをPythonへ渡します。手動ボタンに加え、利用者がONにした場合だけPythonタイマーが同じ処理を呼び出します。対象2店舗以外のページからの取り込みは拒否します。確認・同意・CAPTCHAは自動操作しません。ブラウザと保存処理は別プロセスで、同じSQLiteと`reports`フォルダを使います。保存完了通知はブラウザごとに分け、OFFやページ切替前の古い処理から自動移動が続かないようにします。

Selenium自動収集（`collector.py`、PC版UIからは削除・コマンドライン専用）は、Python + Seleniumで通常のChromeを起動し、公開画面のリンク・日付選択を操作します。
操作間隔は最低3秒、ブラウザは1つ。IP変更・自動操作の偽装・認証回避はありません。
同意操作は自動化していません。利用規約への同意は自動収集の許諾を意味しません。
アクセス制限、表示形式の変更、日付や数値の不一致を検出した場合は停止します。

## 開発・検証

専用環境は `.venv`。Windowsでは `setup_python.cmd` で作成・依存の更新・読み込み検証を行います。既存の `.runtime` は削除しません。詳細は [DEVELOPMENT_CHECKS.md](../DEVELOPMENT_CHECKS.md) を参照してください。OCRはRapidOCRとONNX Runtimeを、ブラウザ直接取り込みは`pywebview`を使用します。
`.venv\Scripts\python.exe -m unittest discover -s tests -v` で採点・履歴保持・日付整合性・表とグラフの抽出検証を行います（実サイトへのアクセスは伴いません）。

## 初回に確認した実データ

`observed_tables.json` と `observed_graphs.json` は、サイドブラウザーで本人が規約に同意した後に、画面上の表とSVGグラフを照合して記録した 2026-09-08〜13 の戦国乙女5・84台分です。`import_observed.py` を実行すると、SQLiteへ保存して9月13日分の結果表を再生成できます。

この初期取り込みは通常Chromeの自動取得が成功したことを意味しません。通常Chrome側はブラウザ接続が切れる現象を確認しており、原因の調査と修正は未完了です。
