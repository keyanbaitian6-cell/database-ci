# database（試作版）

メルヘンワールド長町南店とスーパーメルヘンワールド幸町の1000円46枚スロットだけを対象とする、個人用のローカルツールです。
`start.cmd` をダブルクリックして起動します。入力方法はAndroid版と同じく、アプリ内ブラウザでの直接取り込みだけです。PC版のメイン画面には「ブラウザで取り込む」「バックアップ」「結果・履歴」の3つしかありません。

## Windows版EXE

`bin\database\database.exe` を起動すると、PythonのインストールなしでPC版を使えます。`bin` フォルダは、`database` フォルダと `database-browser` フォルダを含めたまま置いてください。メイン画面の「ブラウザで取り込む」を押すと、補助プログラム `bin\database-browser\database-browser.exe` が自動で起動します。

この配布物は、プロジェクト内の既存の `database\data` と `database\reports` を優先して使います。したがって、現在の記録を引き継ぐ場合はEXEだけを取り出さず、リポジトリの `database` フォルダ内に `bin` を置いた状態で起動してください。EXEのビルド時に既存データをコピーしたり初期化したりはしません。実サイトの規約画面や実ページでの取り込み動作は、自動ビルド検査の対象外です。

## ブラウザで直接取り込む

1. メイン画面の「ブラウザで取り込む」から「ブラウザを開く」を押すと、別ウィンドウで対象2店舗専用のブラウザが開きます。
2. ブラウザ内で店舗・機種・日付は自分で選びます（自動操作はしません）。利用規約への同意が出た場合もご自身で操作してください。画面右上のカードには、もう一方の店舗を開くボタンもあります（ドラッグで好きな位置に動かせます）。
3. 機種別の一覧ページで「この表を取り込む」を押すと、今表示されているHTMLの表を直接読み取り、その場で保存します（確認画面はありません。スクリーンショットもOCRも使いません）。台番号・BB・RB・総回転数・前日最終スタート・最大持玉を取得し、URLの`target_date`があればそれを保存日として最優先します。台番号が重複していたら、勝手に削除・統合せずエラーで知らせて保存を止めます。未稼働台や数値が同じ連続台も、別台としてそのまま保存します。幸町店の一覧には最大持玉の列自体が無いため、その場合は最大持玉なしで保存し、個別グラフページ側の表示から後で埋まります。
4. 個別台のグラフページで「このグラフを取り込む」を押すと、別ウィンドウでSVGグラフの座標からゼロ線・最高点・最低点・終点を自動検出した確認画面が開きます。位置を確認・修正し、ウィンドウ右上の「採点を確定」を押す（またはEnterキー、キャンセルはEsc）と保存します。グラフ画面に機種名が出ない場合も、先に取り込んだ同じ店舗・日付・台番号の一覧から機種名と数値を自動で引き継ぐため、空欄にはなりません（先に一覧を取り込んでいない台のグラフは取り込めません）。一覧取り込み後に詳細画面側の総回転数・最大持玉が増えている場合は、詳細画面の値を採用し、確認画面のキャプションにその旨を表示します。
5. グラフを保存すると、同じ機種・日付でまだグラフを取り込んでいない台へブラウザが自動で移動します（サイト自身が発行したその台のリンクを使うだけで、クリックやフォーム送信の自動化はしません。次に取り込むかどうかは引き続きご自身の判断です）。オーバーレイの「次の未取り込み台へ」を押しても同じ動きを手動で行えます。
6. 保存した縮小グラフと4点座標はSQLiteに記録されます。
7. メイン画面の「選んだ機種の結果を開く」「過去の記録を見る」で確認します。

対象は長町南店・幸町店の1000円46枚スロット（`kind_code=21`）だけです。対象外のURLへは遷移できないよう自動で戻し、対象外ページからのデータ取り込みも拒否します。同意操作の自動化、IP変更、アクセス制限の回避はしません。マウス操作の自動連打・自動巡回（人間並みの速度に抑えたものを含む）も実装しません。幸町店の利用規約にあるスクレイピング禁止条項と、このプロジェクトが一貫して守ってきた「取り込みは1クリック＝1回の明示的な人の操作」という原則によるものです。外部サービスへ画像・台データを送信しません。

## Android版とバックアップを共有する

「バックアップ（Google Driveなどで共有）」から、保存データをJSONファイルとして書き出し・読み込みできます。ClaudeやこのPCアプリ自体はGoogle Driveを直接操作しません。Google Drive for Desktopの同期フォルダや、ブラウザでのDriveへの手動アップロードなど、ご自身の操作でファイルを共有してください。Android版も同じ形式のファイルを「バックアップを共有（書き出し）」「バックアップを読み込む」から扱えます（Android側はファイル選択画面からGoogle Drive上のファイルを直接選べるため、Android側にもGoogle API連携は不要です）。

1. 「バックアップを書き出す」の隣で店舗・日付を選べます（それぞれ「すべての店舗」「すべての日付」も選べます）。絞り込むと、その範囲の全機種だけを書き出します。
2. そのファイルをAndroid版で「バックアップを読み込む」から選ぶと取り込めます（逆にAndroid版で書き出したファイルをPC版で読み込むこともできます。Android版も書き出し時に店舗・日付を選べます）。
3. 取り込み時、同じ店舗・日付・機種・台番号で数値（総回転数・BB・RB・最大持玉）が食い違う記録は自動で上書きしません。新規記録とグラフのみの追加は自動反映し、数値が食い違う記録は確認画面に一覧表示するので、必要なものだけチェックして反映します。
4. PC版のSelenium取得由来の生グラフ（`graph`）はAndroid版のスキーマにない形式のため、バックアップ経由では数値のみ引き継がれ、グラフ画像は引き継がれません（`graph_measurement`形式のグラフは双方向で引き継がれます）。

## スクリーンショットOCR・Chrome拡張・Selenium自動収集について

これらはPC版のメイン画面から削除しました（ブラウザ直接取り込みで置き換わったため）。裏側のコードとテストは残っています。

- `screenshot_import.py`（端末内OCR）と `collector.py`（Selenium自動収集）は、モジュールとしてはそのまま存在し、`python -m unittest discover -s tests -v` のテスト対象です。
- `collector.py` は単独のコマンドラインからは引き続き使えます：`python collector.py --url <一覧URL> --date <YYYY-MM-DD>`（`__main__` ブロック参照）。
- `chrome_extension` フォルダとその撮影機能自体は変更していませんが、PC版アプリはもう撮影フォルダを監視・自動取り込みしません。
- これらをPC版UIへ復元したい場合は、`app.py` の以前のコミット相当（履歴なしリポジトリのため `AI_COLLABORATION.md` の記録を参照）を基に作り直してください。

## 現段階の範囲

- ブラウザ直接取り込み：アプリ内ブラウザで対象2店舗を開き、機種別一覧のHTML表と個別グラフのSVGから、台番号・BB・RB・総回転数・前日最終スタート・最大持玉・ゼロ線/最高点/最低点/終点を直接取得します。店舗・機種・日付の選択は利用者本人の操作です。
- 一覧の取り込みは確認画面なしでそのまま保存します（HTML直読みのためOCRのような誤読がなく、`build_table_rows`が見出し不一致・台番号重複・対象外区分などを事前にエラーで止めます）。グラフの取り込みは4点確認画面を経て保存します。
- URLの`target_date`を保存日として最優先し、台番号の重複は保存前にエラーで知らせます（自動削除・自動統合はしません）。未稼働台や数値が同じ連続台も個別に保存します。
- グラフページに機種名が出ない場合は、同じ店舗・日付・台番号で先に取り込んだ一覧から機種名と表の数値を自動で引き継ぎます。
- 新規に保存したグラフは、実際の縮小画像と4点座標をSQLiteへ保存します。
- メイン画面の店舗・日付・機種名は自由入力ではなく、保存済みの組み合わせだけを選べるプルダウンです（「選んだ機種の結果を開く」「台記録を削除」で使用）。
- 幸町店の一覧ページには最大持玉の列が無いため、`max_hold`が無いまま保存されることがあります（個別グラフページ側の表示から後で埋まります）。結果表・過去の記録では「—」で表示し、採点は最大持玉の比較データ不足として扱います。
- 現行の配点ではゼロ線・最高点・終点を採点に使い、最低点はグラフ形状の記録として保持。
- 表示G、BB、RB、最大持玉、グラフの描画座標、出典URL/ページをSQLiteに日付別保存。
- 再取得時も過去日を保持し、取得履歴も別表に追加。数値が同じなら既存グラフを保持し、数値が訂正された場合は対応しない古いグラフを採点から外します。
- HTMLの結果表と、機械可読なJSONを `reports` に出力。
- 店舗・日付・機種で絞り込める過去記録画面を `reports/database-history.html` に更新。台番号を押すと、保存済みのスランプグラフ（実画像、または元画像がない場合は4点から復元した概略グラフ）をその場で確認できます。
- 全機種の一括取得、Excel出力、島図、末尾集計、自動定時実行は未実装です。

## 採点（2026-09-25-v10）

[採点仕様書](../SCORING_POLICY.md)を正とします。
当たり頻度60点、最大持玉20点、終点10点、維持10点。回転数は加点せず、比較対象の選定と縮約に使います。
同店・同機種・過去30日の回転数が近い台で比較し、当日・未来は使いません。
当日500G以下の台は採点しません（「保留」表示）。
少数の比較は中立へ縮約し（v9で、3つの薄さの目安を掛け算から相乗平均に変更）、欠測項目は中立補完した暫定点・評価可能配点・欠測幅を表示します。
最大持玉は、枚数そのものによる点（19,000枚のコンプリート上限で満点）が順位による点を上回ればそちらを使います。引き上げにだけ使い、下げることはありません。
これは実績の独自評価です。設定確率・明日の勝率・期待収支はわかりません。
台番号別の当たり頻度の過去傾向に基づく「翌日候補（仮）」を、同じ機種で3日以上の履歴があり、候補化できる台が4台以上ある場合だけ表示します。採点とは独立し、翌日の優位性は検証中です。
保存済み記録は再取得不要。新しい結果・履歴画面を開くと再計算します。旧HTMLを直接開くと旧点数のままです。

検証：`python -m unittest discover -s tests -q`、読み取り専用全件監査：`python audit_scoring.py`。
監査結果は `reports/scoring-v8-audit/` に保存されます。

## 取得方法と制限

ブラウザ直接取り込みは、`pywebview`（Windowsでは WebView2）で対象2店舗だけを表示するウィンドウを開き、店舗・機種・日付の選択を含めて通常の人の操作を前提にしています。ページに注入した2つのボタンが、その時点でブラウザに表示されているHTMLの表またはSVGグラフをそのままPythonへ渡すだけで、クリックやフォーム送信などの操作は自動化しません。対象2店舗以外のURLへ移動した場合は元の画面へ戻し、対象外のページからの取り込みも拒否します。同意操作は自動化していません。利用規約への同意は自動収集の許諾を意味しません。実サイトのHTML構造が変わった場合、表・グラフの検出に失敗しエラーで知らせます。ブラウザ画面は`app.py`とは別プロセスで起動し、同じSQLiteファイルと`reports`フォルダを共有します。

Selenium自動収集（`collector.py`、PC版UIからは削除・コマンドライン専用）は、Python + Seleniumで通常のChromeを起動し、公開画面のリンク・日付選択を操作します。
操作間隔は最低3秒、ブラウザは1つ。IP変更・自動操作の偽装・認証回避はありません。
同意操作は自動化していません。利用規約への同意は自動収集の許諾を意味しません。
アクセス制限、表示形式の変更、日付や数値の不一致を検出した場合は停止します。

## 開発・検証

専用環境は `.runtime`。再作成時は `py -3.14 -m venv .runtime`、その環境へ `pip install -r requirements.txt`。OCRはRapidOCRとONNX Runtimeを、ブラウザ直接取り込みは`pywebview`を使用します。
`python -m unittest discover -s tests -v` で採点・履歴保持・日付整合性・表とグラフの抽出検証を行います（実サイトへのアクセスは伴いません）。

ブラウザ直接取り込みの実サイトに対する動作（規約同意画面の表示、実際のHTML/SVG構造との一致）は自動テストの対象外で、人が対象サイトを開いて確認する必要があります。
