# database HTMLデータ変換（Windows）

`start.cmd` をダブルクリックして起動します。EXEの作成・インストールは不要です。
databaseのPC版と同じ配色・部品を使用する別ウィンドウのアプリです。

1. **HTMLを選ぶ（複数日可）** から、保存HTMLを選びます。
2. 日付・台数と、機種名の対応を確認します。
3. 未確認の機種を選び、候補または既存機種一覧から選択し、**この対応を確定** を押します。
   元の機種名を使う、対象から外す、も選択できます。
4. **補完用JSONを保存** を押します。
5. PC版databaseを再起動し、**バックアップ・同期 → バックアップを読み込む** からJSONを選びます。
   P-STATIONはP’s CUBE専用の記録へ、幸町はメルヘンの幸町の記録へ振り分けられます。

店舗はHTMLの見出し（「YYYY/MM/DD 店名 データまとめ」）で判定し、画面上部に表示します。1回に選べるのは1店舗のHTMLだけです。

機種名は半角・全角・空白・記号とL/LB/スマスロの接頭表記を整えて、一意に一致するものを補完します。
似ているだけの名前は自動確定しません。候補は文字列の類似度であり、同一機種の保証ではありません。
確定した対応はP-STATIONは `html_converter/data/machine_names.json`、幸町は `machine_names_saiwaichou.json` に保存し、次回も使用します。
複数日にまたがる機種も、名前の対応は1回で済みます。

- 取得画面の **店舗** で「幸町」を選ぶと、一覧URLが幸町の一覧に、保存先の初期値が `downloaded_htmls/saiwaichou` に切り替わります。

- 変換先はメルヘン用DB（`database.sqlite3`、店舗 `saiwaichou`、1000円46枚）です。JSONの初期名は `database-backup-anaslo-saiwaichou-日付.json`。
- **databaseに保存済みの日付・台番号は出力しません**（機種名の表記が違っても既存を優先し、別名で2台目を作りません）。
- **databaseに一度も記録のない台番号は出力しません。** HTMLに貸玉が無く、メルヘン用DBは1000円46枚だけのためです。2026/9/1のHTMLでは560台のうち、記録がないのはブラックボード8台だけでした。

- 機種名の自動対応は、①メルヘンの表記（★、先頭のL/S/LB/SB、スマスロ・パチスロ、末尾の短い英数字の記号）を除くと名前が一致し、②その名前がメルヘンで同じ台番号に保存されたことがある、の両方を満たし、1機種に決まるときだけです。台番号だけ一致する名前は候補の上位に出すだけで、確定はしません（入替があるため）。
- 2026/9/1の実HTML（142機種）では81機種が自動対応になりました。目で見た範囲では誤りはありませんでしたが、残りと合わせて保存前に一覧で確認してください。
- 取り込み後は通常のメルヘンの記録として扱われ、採点・翌日候補の過去データにも入ります（P-STATIONの補完のような除外はしていません。2026-10-16 利用者がこの扱いに決定）。閲覧用ファイルには出典の印が出ません。
- メルヘンが一部の台だけ★などの記号付きで記録している機種（例：海門決戦の1278番台）は、その台だけメルヘンの表記で保存します（2026-10-17）。
- 対応表を直したあと、保存済みの補完の機種名を合わせるには、PC版と変換アプリを閉じて `database` で `python fix_anaslo_saved.py`（表示だけ）→ `python fix_anaslo_saved.py --apply`。修正前のDBを複製し、古い名前の行は削除の印を付けて消すので、古いJSONを読み直しても戻りません。
- 差枚はアナスロに無く、グラフも縮尺が分からないため、補完の行には推定差枚・最大持玉が出ません。グラフは同じホールのグラフを片側1000に引き伸ばしたもの（ジャグラーオンラインの差枚で確認）なので、メルヘンと同じ座標の測定値（`graph_measurement`、`method: anaslo-source-graph`）に変換して保存します（2026-10-17）。採点の終点・維持（20点）とバラエティの終わり方に使われ、重なる日のメルヘンとの一致は99.6〜99.9%。最大持玉の点は今までどおり中立で補完します。

## 一覧から指定期間のHTMLを取得する

1. **一覧から取得** を押します。
2. **開始日・終了日の「カレンダー」から日付を選択** します。両端の日付を含みます。YYYY-MM-DDの手入力も可能です。
3. 一覧URLを使うか、**保存した一覧HTML** を選んでチェックを付けます。
   保存HTMLを使う場合、一覧ページへの通信は発生しません。
4. **指定期間のリンクを確認** を押します。一覧URL＋ブラウザ方式では一覧を表示し、本人が確認後に上部 **取得 → 表示を確認して自動取得を開始** を選びます。親画面に表示された日付・件数を確認します。
5. HTML保存先を確認し、**表示中の日付のHTMLを取得** を押します。オンライン一覧の取得後は同じブラウザを55秒間保持するので、その間に開始してください。日別取得で別の窓は作り直しません。
6. オンライン一覧で確認済みなら、そのブラウザの通常リンク遷移で日別へ進み、確認メニューを再度押す必要はありません。保存した一覧HTML＋ブラウザ方式では、最初の日別ページの表示を本人が確認し、同じメニューから開始します。
7. 1日分のHTMLを保存したら、指定範囲内の次の日付へ自動で進みます。保存済みの日は再取得しません。完了・停止時は取得ブラウザを閉じます。
8. **取得・確認できたHTMLを変換画面へ渡す** を押し、従来どおり機種名を確認してJSONを保存します。

一覧URLをブラウザで取得する場合、一覧の表示確認から日別取得完了まで同一プロセス・同一セッションを使います。
プレビュー後55秒間操作しなければ閉じ、一覧の再確認を案内します。子プロセス側にも60秒の無要求終了を設けています。
入力変更・閉じる・エラーでも保持したブラウザを終了します。完了/停止後の次の取得は、一覧の確認から開始してください。
保存した一覧HTMLを使えば、一覧用ブラウザを開かず日別HTMLの取得から始められます。
カレンダーは前月/翌月と年/月指定に対応。選んだ日付が入力欄に入り、期間を変えればリンク確認が必要になります。

ブラウザ方式は既存PCのpywebview/WebView2を使い、変換画面とは別のプロセスで動きます。

## 取り込み規則

- 同じ店舗・貸玉・営業日・台番号に既存の記録がある場合、機種名の表記が違っても既存記録を保持します。
- 再取り込みによる重複追加はありません。
- MY・差枚・観測時刻・P’s CUBE専用台URLは、存在しない値を埋めずnullにします。
- 出典URL・元機種名・元ファイルSHA-256・掲載確率・グラフの原座標を記録に保持します。
- グラフの枚数換算が不明なため、通常の差枚グラフへは変換しません。
- アナスロのBB/RB/ARTとP’s CUBE信号の同一性は全機種で未確認です。補完履歴は採点・翌日候補の比較データから除外します。
- 沖ドキは既存アプリのルールに従い対象外です。
- 後から同じ機種・台・日付のP’s CUBEデータを取得した場合、実取得データを優先します。
- JSON全体の検査に失敗した場合、途中までの書き込みは行いません。
- 変換アプリは既存DBを読み取り専用で参照し、反映はdatabase側でJSONを読み込んだときに行います。
- JSONの保存先に同名ファイルがある場合は上書きしません。別名で保存してください。
