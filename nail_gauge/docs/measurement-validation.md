# 釘間隔の推定 検証計画（nail_gauge）

作成：2026-10-31 Claude（計画のみ。まだ1件も実施していない）
関連：[design.md](design.md)（§A-6 の仮説 H1〜H8、§C の計算と誤差の要因）、[implementation-plan.md](implementation-plan.md)

## 1. 目的と原則

- 「画像から出した推定値」が真の寸法とどれだけ違うか（指標E）と、写真ごとのばらつき（指標S）を、**分けて**測る。
- 実測していないうちは、精度・信頼度を数値で言わない。下に書く数値の目標はすべて **仮の目標** で、達成したかどうかは検証の結果で決める。
- 検証の条件・判断の基準は、結果を見る前に決めて書き残す（このリポジトリの翌日候補の検証と同じやり方：事前に固定してから見る）。結果を見てから基準を動かした場合は、その事実を記録し、その結果を「検証済み」と呼ばない。
- 調整に使ったデータと、性能を確かめるデータを分ける（§6）。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 真値 | ノギス・すきまゲージ・ピンゲージなど、カメラ以外の方法で測った寸法。測り方と道具の分解能も記録する |
| 誤差 e | `推定値 − 真値`（mm）。偏り（e の平均・中央値）と、散らばり（e の標準偏差）を分けて見る |
| 指定のばらつき | 同じ画像に点を置き直したときの推定値の散らばり |
| 撮り直しのばらつき | 同じ対象を撮り直したときの推定値の散らばり（指定のばらつきを含む） |
| 標準条件 | 正面（目測）・撮影距離 約15cm【仮】・玉と対象が画像の中央付近で、玉の直径の2倍以内に並ぶ・ライト消灯・主カメラ・ズーム1倍 |

## 3. 検証の段階

### V0 計算と座標変換（真値が厳密に分かる合成データ）

- 目的：式・円の当てはめ・EXIFの向き・拡大移動の座標変換に、実装の誤りが無いこと。
- データ：`tool/make_synthetic_images.dart` で作る画像。白地に、直径が既知の円（玉の代わり、例 200.0画素）と、間隔が既知の2つの円（釘頭の代わり）を描く。縁は面積で塗る（半画素の位置まで表す）。EXIFの向き1〜8を付けた版も作る。
- 確かめること：
  - 計算：既知の点を与えて `estimate_mm` が式どおり（浮動小数の誤差の範囲、例 1e-9 mm以内）。
  - 円の当てはめ：円周上の点（ノイズ無し）から直径が一致、ノイズ（標準偏差0.5画素）を足したとき、弧の角度ごとの直径の散らばり（狭い弧の注意の閾値を決める材料）。
  - 向き：8種類それぞれで、正規化後の画像の印の画素が、R→C の表（[design.md](design.md) §C-6-2）で計算した位置と一致。
  - 画面座標：拡大率 1・2.5・10倍、移動あり、表示用縮小 s=0.5 で、画面の点→保存の点→画面の点が往復して0.01画素以内。
- 合否：すべて一致すること（これは仮の目標ではなく、実装の正しさの条件）。

### V0b 端末のカメラの性質（方眼）

- 目的：レンズの歪みの残り、プレビューと保存画像の範囲の対応、近距離でのレンズの切り替わりの有無。
- データ：印刷した方眼（1mm・5mm）。印刷の倍率はノギスで実測して記録する（印刷は縮むことがある）。正面・約15cm【仮】で撮る。
- 確かめること：画像の中央と端で、5mmの升目の画素数の違い。ガイド枠の推定位置と、実際に写った方眼の位置の違い。撮影距離を10〜30cmで変えたとき、画角が急に変わる（別のレンズに切り替わった）か。
- 記録：機種、`camera` が返したカメラ名、解像度、ズーム。

### V1 既知寸法の模型（標準条件）

- 目的：玉を基準にした推定の、標準条件での誤差（偏りと散らばり）。
- 模型：
  - 板に釘を2本打つ（実際のパチンコの釘が手に入れば使う。無ければ頭の付いた細い釘）。間隔はすきまゲージ・ピンゲージで決め、**頭の内側の縁の間・軸の間をそれぞれノギスで実測**する。数通り（例：8・9・10・11・12mm【仮】）作る。
  - 釘頭の板からの高さを実測し、記録する。
  - 本物のパチンコ玉（無ければ直径をノギスで測った11mm前後の鋼球）を、釘の近くに置く（置いた玉は動かないので、ぶれの影響を除いて測れる）。玉の直径も実測し、設定の「実測直径」に入れる。
  - ガラス板（写真立ての板など）を板から実機に近い距離【要確認】に立てる版と、ガラス無しの版を作る。
- 手順：各間隔で、標準条件で10枚撮る。各写真で、定義 `heso_head_inner` と `heso_head_center` の両方を測る。
- 見る値：定義ごとに、誤差 e の中央値（偏り）と標準偏差。真値として「頭の内側の縁の間」と「軸の間」の両方と比べ、どちらにどれだけ近いかを記録する（[design.md](design.md) H3）。

### V2 同じ画像の指定し直し

- 目的：点を置く人の揺れ（指定のばらつき）。
- 手順：V1の画像から5枚を選び、それぞれ10回、点をすべて置き直す。前回の点が見えない状態で行う。日を分ける（同じ日に続けて行うと、前の位置を覚えている）。
- 見る値：画像ごとの推定値の標準偏差。玉の直径の画素数・対象の画素数の標準偏差（画素）も分けて見る（どちらの揺れが大きいか）。
- 参考の計算：1画素が何mmかを画像ごとに出し、「0.1mmが何画素か」と並べる。

### V3 同じ対象の撮り直し

- 目的：撮り直しのばらつき（S）。
- 手順：V1の模型の1つの間隔で、構え直して20枚撮る（毎回、端末を離して構え直す）。各写真を1回ずつ指定する。
- 見る値：推定値の標準偏差、範囲、中央値。V2のばらつきと比べ、撮影による分を見積もる（独立とみなせるなら、撮影による分 ≈ √(V3² − V2²)。独立でない可能性も書く）。
- 平均で減るかの確認：20枚から n=1・3・5・10枚を何通りも選び、中央値の誤差 e の散らばりが n とともにどう減るかを見る。減り方が止まる所が、減らせない誤差（偏り）の目安。

### V4 条件による影響

- 目的：どの条件で誤差が増えるかを知り、撮影条件の制限を決める材料にする。
- 1度に1つの条件だけ変え、ほかは標準条件にする。各条件で10枚。

| 条件 | 変える値【仮】 | 関係する仮説 |
|---|---|---|
| 撮影距離 | 10・15・20・30cm | H2（距離で奥行きの差の割合が変わる）、H7 |
| 角度（左右・上下） | 0・5・10・15度（分度器と台で決める） | H4 |
| 玉の位置 | 対象のすぐ横・玉2個分離す・5個分離す・画像の端 | §C-3-2、§C-3-3 |
| 釘頭の高さ | 板から玉の中心と同じ高さ・＋5mm・＋10mm（模型で変える） | H2 |
| 照明 | 室内灯・明るいLED・端末のライト・斜めからの強い光 | §C-3-4（反射） |
| ガラス | 無し・有り・有りで5度傾けて撮る | H5 |
| 端末 | 手元の端末（2台以上あれば） | H7 |
| ズーム | 1倍・2倍（デジタル） | H7 |

- 見る値：条件ごとの誤差 e の中央値と標準偏差、標準条件との差。理屈の式（[design.md](design.md) §C-3）の予想と並べる（理屈に合うなら補正や条件の制限の根拠になる。合わないなら別の要因を探す）。

### V5 動く玉・連写（段階2の前提）

- 目的：動いている玉を基準に使えるか（H1）。
- 手順：模型を傾けて玉を転がし、連写（または動画）で撮る。止めた玉の写真と比べる。
- 見る値：連写のうち、ぶれが小さく輪郭が見える写真の割合。その写真での推定値と、止めた玉の推定値の差。動く向きに直交する直径を使ったときの差。

### V6 実機（できる範囲で）

- 店で撮るときは、店舗の撮影のルールに従う。ルールで撮れない場合はこの段階は行わない。
- 店の台では真値が分からないので、**誤差（E）は求められない**。分かるのは、撮り直しのばらつき（S）、使える写真の割合（H1）、日をまたいだ値の並び（相対比較）だけ。
- 真値が要る場合は、家で使える実機（中古の盤面など）で、盤面を外して釘の間隔を実測する。手に入るかは利用者の判断。

## 4. 記録の形

- 検証ごとにフォルダを作り、次を残す：写真（アプリが保存したもの）、アプリのDBの写し、真値の表（CSV：対象ID、定義、真値mm、道具、測った人・日）、条件の表、結果の表、事前に決めた基準を書いた計画のメモ。
- 写真・DBは利用者の手元に置く。GitHubには、真値と結果の表、計画と報告の文書だけ上げる（店・台の写真は上げない）。
- アプリの「書き出し」（実装計画T11）で、測定とその結果をCSV・JSONで出せるようにする。

## 5. 合否の基準

### 5-1. 実装の正しさ（必須、満たさなければ次へ進まない）

- V0：すべての試験が一致。

### 5-2. 仮の目標（検証の前に決めておく値。満たすかは未確認）

| 項目 | 仮の目標 | 根拠 |
|---|---|---|
| 指定のばらつき（V2） | 推定値の標準偏差 0.1mm以下 | 表示が小数第1位なので、置き直しだけで表示の桁が揺れないこと |
| 撮り直しのばらつき（V3） | 標準偏差 0.2mm以下 | 日をまたいだ相対比較で、0.5mm程度の変化を見分けたいという想定【利用者に確認】 |
| 標準条件の偏り（V1） | 誤差の中央値の絶対値 0.3mm以下（定義ごと） | 同上 |
| 条件による悪化（V4） | 標準条件から角度10度以内・距離10〜20cmで、偏りの増加が0.2mm以下 | 片手で構えて保てそうな範囲【仮】 |

数値は、利用者が「何mmの違いを見分けたいか」によって変わる。最初の検証の前に利用者と決め、この表を更新する。

### 5-3. 検証済みの性能（検証のあとに書く）

- 書き方：「条件（標準条件・機種・定義・玉の実測直径）で、n枚・k個の間隔について、誤差の中央値 ○mm、95%の範囲 ○〜○mm（検証日、検証用データで）」。
- アプリの画面に出すのは、この形で書けた条件だけ。条件が合わない測定（角度の印が無い、玉が遠い等）には出さない。
- 画像品質の印・検出の点数を、この誤差の範囲に読み替えない。

## 6. 調整用データと検証用データの分離

- 閾値（玉が小さすぎる、玉が遠い、弧が狭い等）や補正（奥行きの差の補正、楕円の扱い）を決めるのに使った写真は **調整用**。
- 性能を報告する写真は **検証用**。調整用と別の日に、別の模型の間隔（真値を、調整が終わるまで見ない）で撮る。
- 検証用データで結果を見たあとに閾値・補正を変えたら、そのデータは調整用に移し、次の検証用データを新しく作る。
- 段階3の自動検出の学習・調整に使う写真も、同じ考えで分ける（検出器の評価は、手で置いた点との差と、真値との差の両方で行う）。

## 7. 精度が足りなかったときの判断

結果を見る前に、次の分かれ道を決めておく。

| 結果 | 判断 |
|---|---|
| V0が一致しない | 実装の誤り。直すまで先へ進まない |
| V2の指定のばらつきが大きい（仮の目標の2倍超） | ルーペ・微調整・円周の点の方式を改める。玉の画素数を増やす（近づく）案内にする。それでも大きければ、表示を整数mmにするか、玉に対する比だけを出す |
| V3は小さいが、V1の偏りが大きく、条件によらず一定 | 偏りの原因（定義、奥行きの差）を調べる。原因が説明でき、模型で補正が効くなら、補正を版として入れ、新しい検証用データで確かめる。説明できなければ、**相対比較に切り替える**：同じ台・同じ箇所・同じ撮り方での前回との差として表示し、絶対値は参考に下げる |
| 偏りが角度・距離・玉の位置で大きく変わる | **撮影条件を制限する**：悪化が仮の目標以内の範囲を「標準の撮り方」とし、範囲外を注意・無効にする（例：玉が遠い・画像の端は無効）。範囲外を見分ける手がかり（玉の楕円の度合い、傾きの目盛り）が実際に効くかも確かめる |
| V3のばらつきが大きく、枚数を増やすと減る | 段階2（複数枚の中央値）を標準の測り方にする。必要な枚数をV3の結果から決める |
| V3のばらつきが大きく、枚数を増やしても減らない | 撮影ごとに違う偏り（構え・照明）がある。撮影支援（段階3の品質判定）を先に検討する |
| V5で、使える写真がほとんど取れない | 動く玉を基準にする方式を見直す。止まった玉が写る場面の限定、機種ごとの既知の寸法（役物・枠など）を基準にする案（段階3）を比べる |
| どの条件でも、見分けたい差より誤差が大きい | mmの表示をやめ、玉に対する比・前回との比較だけにする。または計画を止める。利用者と相談する |

## 8. 実施の順と、誰が何をするか

1. V0（AIが実装と同時に試験として書く。手元とCIの試験で毎回流す）。
2. V0b・V1・V2・V3（利用者が模型を作り、撮影と点の指定をする。AIは集計のスクリプトと報告を作る）。
3. 5-2の仮の目標と照らし、§7で次を決める。
4. V4・V5（段階2に入る前）。
5. V6（できれば）。

各段階の結果は、日付・機種・アプリの版（コミット）・計算方式の版を付けて、このファイルの後ろか、別の報告ファイルに残す。利用者が手元で測った値と、AIが直接確認した値を区別して書く。
