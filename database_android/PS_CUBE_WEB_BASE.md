# P’s CUBE iOSブラウザ版の土台

利用者の2026-10-01の依頼により、iOSブラウザ版だけのベースを追加した。
既存Flutter閲覧版と同じWeb配布物に含める `web/pscube/` の独立した入口。
2026-10-03に元グラフ由来の差枚を共通モデルへ追加した。採点式は変更していない。

## 現在できること

- Safariで保存した機種一覧・機種内の全台一覧・台別7日履歴のWebアーカイブを、ファイル選択から読む。
- Safariのbinary/XML plistを読み、WebMainResourceのHTMLだけから必要な値を抽出する。保存ページのスクリプト・画像・フレームは実行／取得しない。
- 店舗コード・貸玉・機種・営業日・台番号ごとにBIG、REG、AT/ART、累計ゲーム、MY、グラフを保存・表示する。MYを最大持玉に置き換えない。
- 「ノーマルタイプ／それ以外」を機種単位で指定して保存する。未指定は未設定。
- 機種一覧の台数と読み込んだ台数を比較する。途中までの一覧は「全台は未確認」と表示する。
- 台別ページ由来の日別グラフを「詳細取得済」とする。縮小一覧グラフだけの台は詳細未取得のまま残す。
- 未取得台の実リンクを次に開く。欠番を推測で補わない。
- 専用IndexedDB `database-pscube-viewer` に保存し、再表示・JSON書き出し・再読み込みができる。既存閲覧版のIndexedDBには書き込まない。
- 読み込みは一括検証後に保存。失敗した読み込みで既存データを置き換えない。

## iOSでの操作と制約

配布後の入口は既存閲覧URL配下の `pscube/`（ローカル確認は同じ相対パス）。
2026-10-01に公開済み：https://keyanbaitian6-cell.github.io/database-viewer/pscube/ 。
公開コミット `4075e54`、配信5ファイルの一致とChromiumでの表示を確認（iPhone実機Safariは未確認）。

1. SafariでP’s CUBEを開き、必要なら人が認証する。
2. 対象ページを表示し、機種内一覧は最後までスクロールして台を表示させる。
3. 共有→オプション→Webアーカイブ→ファイルに保存。
4. この画面の「ファイルを読み込む」で選ぶ。
5. 「次の未取得台を開く」でサイトの次の台を開く。保存後に再び読み込む。

通常のSafari Webページは、別オリジンにある認証済みサイトのDOMを直接読めない。
したがって、Android内部WebViewと同じ「押すだけで取得→自動遷移」を
この土台で達成したとは扱わない。将来その操作を実現するには、Safari拡張などの
明示的な受け渡し方法、または既存の収集端末からのデータ受信が必要。
本版の台ページリンクは通常のリンクとして開く。リンクを開いただけで取得済みにしない。

## データ形式と更新

`format: "pscube-viewer"`, `version: 1`, `machines`, `records`。
JSONとWebアーカイブのどちらも32MiBまで。従来の `database-backup` とは別形式。
グラフはSVGの描画座標であり、厳密な差枚や元の時系列数値ではない。
差枚の元データは別に取得する。台別ページが同一オリジンの `nc-m06-003.php` から読む
`Graph.src.datas.g`（営業日と数値フィールド）・`Graph.src.datas.p`（連続グラフの元数値）を使い、
各営業日の **最後のY値－最初のY値**（`anjYUnit` があれば乗算）を符号付き差枚とする。
MYとは別項目 `net_medals` に保存し、従来のSVG座標からは補完しない。
PC版・Android版の内蔵ブラウザでは、台別ページの通常取り込み時にこの元データも取得する。
iPhone SafariのWebアーカイブ取り込みでは、下記ショートカットで追加取得する。
1つのグラフ応答は最大7日分だが、既存の台番号・日付と一致した記録だけを更新する。
同番号が複数店舗・貸玉に存在する場合は取り込みを止める。

iPhoneではSafariの台別ページで共有シートの「WebページでJavaScriptを実行」に
`tool/pscube_graph_shortcut.js` を設定し、続けて結果をクリップボードにコピーする。
ショートカットはURLに `YMD_biz` があればその日を選び、省略時は日本時間の前日を選ぶ。
取得後、閲覧ページの「差枚の元データを貼り付け」に結果を貼る。JSONファイルとして
保存した場合は従来のファイル選択からも読める。ページ内の認証情報は結果に含めない。
この通信はサイト自身のJavaScriptで行い、閲覧ページからP’s CUBEへ直接接続しない。
「この日のまとめ」の差枚合計・平均には取得済み台数を併記する。沖ドキなどの
除外機種や未収集台があり得るため、全記録に差枚があっても店舗全体の総差枚とは
呼ばない。古い `version: 1` のバックアップも引き続き読める。
一覧グラフの色と台別グラフのクラスをそれぞれ検証し、水平ゼロ線と始点が一致することを確認する。
曲線末尾の描画用 `M0,0 L0,0` を除去する。未知の複数線・不正座標は保存せずエラーにする。

営業日は機種一覧の選択日、台別履歴では保存URLの営業日と相対日列から決める。
重複キーは店舗・貸玉・機種・台番号・営業日。過去日は残し、同じ記録の重複取り込みは増殖しない。
新台・入れ替え後の台別ページも7列の形を確認するが、過去日の数値欄がすべて空でグラフもない列は
省略する。0の記録を作らず、表示された日の数値・グラフだけを保存する。PC・Androidへの読み取り結果には
`missing_history_days` を付け、保存する日との合計が直近7日を過不足なく覆うことを確認する。
この項目はページ読み取り用で、バックアップの形式は変えない。本日や部分的な欠損は引き続きエラーとする。
機種・番号が変わった場合、旧機種・旧番号の履歴は残し、新しい組み合わせで保存する。履歴を推測で移し替えない。
双方にサイトの更新時刻がある場合は古い数値で巻き戻さない。
時刻不明時は累計ゲームの減少を古い取り込みとして扱い、その他は読み込み順を使う。
BIG・REG・AT/ART・累計ゲーム・MYが同じ場合だけ既存の詳細グラフを引き継ぐ。
数値が更新された一覧を読んだ場合は、古い詳細を新しい数値に結び付けず、詳細を再取得対象にする。
当たり0回のグラフも未取得管理の対象とする。

## 検証

```sh
node tool/test_pscube_data.mjs
# Playwrightがインストールされた環境で：
node tool/test_pscube_browser.mjs
# 必要に応じて PLAYWRIGHT_MODULE と CHROMIUM_PATH を指定する。
```

- データテスト9件：MY保持、不正値・日付・リンク、重複、古い取り込み、再取得、途中一覧、再読み込み、貸玉分離、binary plist。
- ブラウザテスト：外部リソース非実行、XMLアーカイブ、途中／全台表示、7日履歴、欠番を含む未取得リンク、機種タイプ、保存復元、JSON往復、失敗時保護、320/390/768pxで横はみ出しなし。
- 利用者提供の実アーカイブ：設置一覧61機種、東京喰種24台、マイジャグラーV33台、1526番台7日分の読み込み成功。東京喰種の当日詳細未取得は24→23台となり、次台リンクが1527になることを確認。
- 実資料・認証情報・抽出済み実記録はGitに追加しない。テストに入れるのは合成資料だけ。
- 元グラフの差枚は合成JSONで正負値・MYとの分離・保存復元・複数店舗での停止を検証。Flutter Webをビルドし、Chromiumで貼り付けから画面表示まで確認。iPhone実機Safariは利用者によるショートカットの取得成功を確認したが、新しい閲覧画面への貼り付け操作は実機未確認。
