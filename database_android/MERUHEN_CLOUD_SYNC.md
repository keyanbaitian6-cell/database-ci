# スマホだけでメルヘン（幸町・長町南）の記録を閲覧・共有へ反映する

日別の差分出力・両閲覧ページの差分読み込みを使う場合は、[差分同期の導入手順](VIEWER_INCREMENTAL_SYNC.md)を先に確認する。標準設定では従来の全件方式を維持する。

Androidで取り込み、Driveへバックアップを書き出したあと、Google側で既存の `database-viewer.json` へ足し込む。PCを起動していなくても、iPhoneの閲覧ページ・共有カレンダーが読むファイルを更新する。P’s CUBE用とは別のスクリプト。

## 初回設定（一度だけ）

1. **「database共有」があるGoogleアカウント**で [Apps Script](https://script.google.com/) を開き、「新しいプロジェクト」を作る。名前は「メルヘン 自動反映」など。スマホで編集しにくい場合はブラウザの「PC版サイト／デスクトップ用Webサイト」を使う。
2. [配布用スクリプト meruhen_cloud_sync.gs](https://github.com/imakurudev-eng/database/blob/main/database_android/tool/meruhen_cloud_sync.gs) の全文をコピーし、新しいプロジェクトの `コード.gs` の中身を置き換えて貼り、保存する。**既存の自分用・共有用・P’s CUBE自動反映プロジェクトには貼らない。**
3. 上の関数選択で **`setupMeruhenCloudSync`** を選び「実行」。求められるGoogle Driveの読み書き・Google Drive APIへの接続・自動実行の許可を確認する。
4. 実行ログに **「設定完了：30分おきにメルヘン（幸町・長町南）のAndroidバックアップを閲覧・共有へ反映します」** と出れば設定完了。ウェブアプリのデプロイ、APK・PCアプリ・閲覧ページの更新は不要。

設定時にすでにあるAndroidバックアップも読む。1回10ファイルまでで、残りは次の実行へ回す。急ぐときは `syncMeruhenCloud` を実行する。設定関数を繰り返してもこの関数のトリガーは1個だけで、他の関数のトリガーは変更しない。

`database-viewer.json` が共有フォルダに必要。無ければ、PC版で一度閲覧用を書き出す。フォルダの候補が複数なら止まるので、先頭の `MERUHEN_FOLDER_ID = ''` の空欄に「database共有」のフォルダID（DriveのURLの `folders/` の後ろ）を入れ、設定関数を再実行する。

## 日々の使い方

1. Androidでいつもどおり取り込む。ジャグラーオンラインの読み取りも保存まで済ませる。
2. **「バックアップを書き出す（共有）」** から、**マイドライブ直下または同じ「database共有」直下**へ保存する。`database-backup-android-YYYYMMDD-HHMMSS.json`（日時なしの `database-backup-android.json` も可）という名前を変えない。
3. Driveへのアップロード完了後、30分おきの自動実行を待ち、iPhoneの閲覧ページ・共有カレンダーを開き直す。急ぐ場合はこの専用プロジェクトで **`syncMeruhenCloud`** を手動実行する。

日付ごとに書き出した複数ファイルも対象。ファイルを分けたことが理由で、最新の1ファイルしか反映されないことはない。アップロード前や保存だけの段階では反映されない。Googleの自動実行・通信・ページ側の更新確認により遅れることがある。

**初回の確認**：アップした日付・店舗・台番号で、iPhoneと共有カレンダーの両方に差枚が出ることを確認する。10/2幸町537番台なら、入力バックアップの `jo_net` が15725である場合、15725枚を表示する。コードの試験は模擬Driveと既存パーサーで実施している。**実Googleでの許可・トリガー実行・iPhone実機への反映は未確認**で、利用者の初回設定後に確認する。

## PCとの関係・反映の規則

- **PC内部の記録（`database.sqlite3`）は更新しない。** 帰宅後は従来どおり「バックアップ・同期」→「バックアップを読み込む」でAndroidの元バックアップを取り込む。Google側に貯める `database-android-cloud.json` はPC用バックアップではなく、これをPCへ読み込ませない。
- PCが閲覧用を書き直しても、Google側で貯めたAndroidの記録を次の実行で足し直す。記録の同一性は店舗・日付・機種名・台番号で判断する。機種名の「+」表記は空白へそろえる。
- 回転数・BB・RB・最大持玉が違う場合は、取得時刻 `captured_at` が新しい方の数値・グラフを採用する。時刻が同じか比較できない場合は元の記録を保持する。タイムゾーンのない時刻は日本時間として読む。同じ数値なら、欠けたグラフ・最大持玉・確定設定を補い、新しい取得時刻も保持する。異なる確定設定が両方にある場合は元の指定を保持する。
- **PCのバックアップ取り込みで競合を「PCの値」に決めても、閲覧用ではAndroidの取得時刻が新しければAndroidの数値になる。** PC内部の競合解決と、閲覧ファイルへの足し込みは別の処理。
- `jo_net`（ジャグラーオンラインの差枚）は、Androidバックアップ同士では `jo_captured_at` の新しい方を保持する。同じ値を再取得した場合も時刻を更新し、後から来た古い値への巻き戻りを防ぐ。PCの閲覧ファイルにはこの差枚の取得時刻がないため、閲覧用への足し込みでは貯めたAndroidの値を優先する。
- 既存の閲覧用の🌈・イベント・候補記録をAndroidの入力で置き換えない。共有の🌈・イベントの別ファイルも変更しない。新しく追加する台の🌈はそのAndroid記録に含まれるものを使う。
- 最新の記録日を含む60日分だけ閲覧用に出し、Google側にもこの期間のAndroid記録を貯める。元バックアップは全期間のまま変更・移動・削除しない。非表示の機種はAndroidから追加しない。グラフ画像は外し、曲線は保持する。

## 状態の確認・停止

専用プロジェクトで **`showMeruhenCloudStatus`** を選んで実行すると、直近の状態・実行日時・件数・閲覧用容量・未処理件数・取り込めないファイルの理由が出る。これは読み取り専用で、表示の時刻はこの確認操作によって更新されない。時刻の末尾 `Z` はUTCで、日本時間は9時間足す。

- 「正常に完了」「一部失敗（ほかは反映済み）」「変更なし」「停止」を表示する。「変更なし」の回も実行日時を更新する。
- 自動実行を確認するには、左の「実行数」で `syncMeruhenCloud` の時間主導型の実行結果を見る。「トリガー」には同じ関数の30分おきの設定が1個ある。
- 止める場合は、この専用プロジェクトの「トリガー」から `syncMeruhenCloud` を削除する。
- 閲覧用が上限48MiBの60%以上、処理時間が2分以上になるとログに注意を出す。

## 失敗した場合・処理の範囲

- 壊れたJSON・形式違い・48MiB超えの入力は、そのファイルだけ取り込まず、他の正常な入力を反映する。新しい失敗があった回だけ、手動・自動の同期をエラーにして知らせる。設定関数は正常な分を反映してトリガー設定まで進む。理由つきの履歴は10件、失敗した版の記録は120件まで保持する。120件を超えた場合は古い失敗版が再試行されることがある。
- 同じ失敗版は読み直さず、ファイルの更新時刻・サイズが変わったら再試行する。入力中の不正な台（店舗・貸玉・日付・必須数値・確定設定など）はPC同様に飛ばす。欠けた必須数値を0に置き換えない。
- 入力読み出しの一時的なDrive障害・アップロード途中の変更は、失敗版として記録せず次回へ回す。蓄積ファイルや閲覧用の一時的な読み出し障害も次回再試行する。
- 蓄積ファイルの破損は、行を黙って捨てず上書き前に止める。復旧が必要な場合は元のファイルを残して確認し、蓄積ファイルを共有フォルダから外す（名前を変える）と次の実行で元のAndroidバックアップから作り直す。
- 閲覧用の形式違い・同名出力の重複・容量超過でも停止する。蓄積を先に保存してから閲覧用を更新し、閲覧用の更新が失敗しても次回に蓄積から再反映する。既存ファイルはID・共有設定を維持してDrive APIのメディア更新を行い、429・5xx・通信例外は1秒・2秒待って合計3回まで試す。
- PCによる処理中の閲覧用更新を保存直前に検知した場合は上書きせず、次回の実行で足し直す。ただしPCとGoogle側は共通ロックを持たないため、最後の確認と書き込みの間の同時更新を完全に排除するものではない。
- 変更なしの回は更新時刻・サイズだけを確認し、大きいJSONは読まず書かない。1回10入力、合計読み込み64MiB・3分を目安に次回へ分ける（最初の1入力は処理する）。入力・蓄積・閲覧用の各ファイルは48MiBまで。
- 対象は「database共有」直下・マイドライブ直下の指定名のAndroidバックアップだけ。下位フォルダ、PCの `database-backup-auto.json`、P’s CUBEのバックアップは読まない。Google Drive内だけの処理で、メルヘン・ジャグラーオンラインへのアクセスは行わない。

## 開発・検証の出典

実装は [meruhen_cloud_sync.gs](tool/meruhen_cloud_sync.gs)、再発試験は [test_meruhen_cloud_sync.mjs](tool/test_meruhen_cloud_sync.mjs)。`node --test database_android/tool/test_meruhen_cloud_sync.mjs` で実行する。全体の確認は `bash database_android/tool/check_before_build.sh`。このスクリプト自体の配布にAPK・PC・Webの公開用ビルドは不要だが、全体確認には閲覧用Webの検証ビルドが含まれる。

互換性の基準はPCの `core._valid_backup_record`・`normalize_machine_name`・`VIEWER_KEYS`・`export_viewer`、既存共有ページの `share_viewer/data.mjs` と閲覧用の `backup_service.dart`。試験は実データそのものではなく、報告された537番台の数値を含む模擬記録を使う。

Google API仕様の出典：[30分おきの時間トリガー](https://developers.google.com/apps-script/reference/script/clock-trigger-builder#everyMinutes(Integer))、[Driveのファイル更新](https://developers.google.com/workspace/drive/api/guides/manage-uploads)、[Apps Scriptの割り当て・上限](https://developers.google.com/apps-script/guides/services/quotas)。実行時間・通信容量の割り当てはGoogle側で変更される場合がある。48MiB・3分・60日はこの実装の設定値。
