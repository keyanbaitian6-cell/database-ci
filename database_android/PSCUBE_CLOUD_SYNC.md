# スマホだけでP’s CUBEの記録を閲覧・共有へ反映する

2026-10-13：Androidで取り込んでDriveへ保存した後、PCで読み込ませないとiPhoneブラウザ版・共有カレンダーが更新されない、という利用者の依頼への対応。

## 初回設定（スマホから一度だけ）

1. **「database共有」があるGoogleアカウント**で https://script.google.com/ を開き、「新しいプロジェクト」を作る。名前は「P’s CUBE 自動反映」など。スマホ表示で編集できない場合はブラウザの「PC版サイト／デスクトップ用Webサイト」を使う。
2. [配布用スクリプト pscube_cloud_sync.gs](https://github.com/imakurudev-eng/database/blob/main/database_android/tool/pscube_cloud_sync.gs) を開き、全文をコピーする。新しいプロジェクトの `コード.gs` に最初から入っている関数を置き換えて貼り、保存する。**既存の自分用・共有用スクリプトの中身を置き換えない。**
3. 上の関数選択で **`setupPscubeCloudSync`** を選んで「実行」。Googleドライブの読み書き、外部サービスへの接続（Google Drive API）、自動実行の許可を求められたら確認して許可する。
4. 実行ログに **「設定完了：30分おきにP’s CUBEを共有へ反映します」** と出れば設定完了。ウェブアプリのデプロイは不要。既存の閲覧ページ・共有リンク・APKはそのまま使える。

旧版の5分おきで設定済みの場合は、この専用プロジェクトのコードを最新版へ貼り替えて保存し、`setupPscubeCloudSync` をもう一度実行する。旧トリガーを30分おきの1個へ置き換える。他の関数のトリガーは変更しない。

すでに30分おきで設定済みで、読み込み元を「マイドライブ直下＋database共有」の両方へ増やす場合は、同じ専用プロジェクトのコードを最新版へ貼り替えて保存するだけでよい。確認を急ぐ場合は `syncPscubeCloud` を手動実行する。

設定時に、Driveへすでに保存されているバックアップも読み込む。入力ファイルが10個を超える場合はログに「残りの未処理ファイル」が出て、残りは次の自動実行で取り込む。

共有フォルダを一意に決められない場合は、スクリプトの先頭の `PSCUBE_FOLDER_ID = ''` の空欄に対象フォルダのIDを入れる。Driveで「database共有」を開いたURLの `folders/` の後ろがID。誤ったフォルダを選ばないため、自動検出で候補が複数あるときは止める。

## 日々の使い方

1. Androidで今までどおり取り込む。
2. 「バックアップを書き出す（共有）」から、**マイドライブ直下または同じ「database共有」フォルダ**へ保存する。どちらも読み込み対象で、ファイル名は変えなくてよい。
3. Driveへのアップロード完了後、次の30分おきの自動実行を待ち、iPhoneの閲覧ページ・共有カレンダーを開き直す。Googleの自動実行・Drive・ページ側の通信状況により遅れることがある。

急ぐときは専用プロジェクトで **`syncPscubeCloud`** を選んで実行する。毎回の設定関数の実行やデプロイは不要。

最初は、アップした日の記録がiPhoneと共有カレンダーの両方に出ることを確認する。コードの試験では模擬Drive・既存ブラウザ読み込み・PCとの互換性を確認済み。**実Googleでの許可・トリガー実行・実機反映は利用者による初回設定後に確認する。**

## 帰宅後のPCとの同期

「database共有」に **`pscube-backup-cloud.json`**（統合済み全期間バックアップ）が追加される。PCの「バックアップ・同期」→ **「P’s CUBEの同期フォルダの最新を読み込む」** で取り込む。AndroidにないPCの過去の記録も、元の `pscube-backup-auto.json` から統合される。

同期前のPCが古い `pscube-viewer-drive.json` を書き直した場合は、Google側の次の自動実行で、統合済みの記録から閲覧用ファイルを再生成する。PC内部のDBへクラウドから自動取り込みする機能は追加していないため、帰宅後は上のボタンで同期する。

## 仕組みと範囲

- 別のApps Scriptプロジェクトで、所有者の許可による30分おきの時間トリガーを使う（利用者の選択、2026-10-13）。公開URL・外部からの書き込み入口は作らない。設定関数を繰り返しても、この関数のトリガーは1個だけ。通常は1日48回、急ぐときは手動で実行する。
- 確認対象は、指定した共有フォルダ直下とマイドライブ直下の `pscube-backup-auto.json`、`pscube-backup-android-YYYYMMDD-HHMMSS.json`、`pscube-backup-pc-YYYYMMDD-HHMMSS.json`。Drive側で名前を絞って検索し、同じファイルIDは一度だけ読む。同内容の別コピーも台ごとの統合で増殖しない。ごみ箱、その他のフォルダ・下位フォルダ、メルヘン、ブラウザの部分バックアップは対象外。元の入力は書き換えたり消したりしない。出力は「database共有」へまとめる。
- 台の統合は既存 `web/pscube/data.mjs` の検証・`mergeData` を生成時に同梱して再利用する。取得時刻が新しい数値を採用し、時刻不明なら回転数で比較。同じ数値なら詳細グラフ・取得済み差枚を保持する。店舗・貸玉・機種・台番号・日付を分け、入力にない記録は消さない。
- 機種タイプは新しく処理したバックアップの明示的な指定を優先、未指定なら既存値を保持する。イベントは入力時刻が新しい方（消した印も含む）。共有イベント・🌈の別ファイルはそのままで、既存の読み込み処理が引き続き使う。
- `pscube-backup-cloud.json` は全期間・グラフ全点・取り込み済み印を保持。数値が変わった台の古い印は引き継がない。既存PC・Androidのバックアップ読み込みで使用できる。
- `pscube-viewer-drive.json` は従来どおり最新の記録日から31日分、グラフ最大16点。始点・終点・最高点・最低点・ゼロ線を保持する。既存ファイルのID・共有設定を維持して更新するので、両方の閲覧用スクリプトは変更不要。
- 変更がないときはファイルの更新時刻・サイズのチェックだけで終わり、大きいJSONを読み直さない。一度に10ファイルまで処理し、読み込み合計64MiB・処理時間3分を目安に、大きい入力は次回へ分けて書き出し時間を確保する。途中で不正なファイルがあれば、その回は統合結果を書かず、実行エラーにファイル名と理由を出す。直して次の実行を待てば再試行する。
- 全期間バックアップを先に確定してから閲覧用を更新。閲覧用の更新が失敗しても、次の実行で統合済みバックアップからやり直す。
- Driveの文字列書き込みAPIの10MB制限を避け、新規ファイルはBlob、既存ファイルはDrive APIのメディア更新を使用する。入力・統合出力は48MiBまで（UrlFetchのリクエスト容量に余裕を持たせる）。全期間20万件、閲覧用10万件まで。容量・件数を超えたら既存出力を置き換えずエラーにする。その場合は分割方式への追加対応が必要。
- 自動処理はGoogle Drive内だけ。P’s CUBEへ接続・追加取得は行わない。PCを動かし続ける必要はない。

## 止める・エラーを確認する

専用プロジェクトの時計アイコン「トリガー」で `syncPscubeCloud` のトリガーを削除すれば自動実行が止まる。閲覧用・共有用の既存プロジェクトは操作しない。

失敗は「実行数」で確認する。フォルダに同名の出力ファイルが複数ある場合、不正なバックアップがある場合、容量を超える場合は明示的に止める。Drive APIの失敗はHTTP番号だけをログへ出し、認証情報は出さない。

## 開発・再発確認

`tool/pscube_cloud_sync_runtime.js` と共通パーサーから `node database_android/tool/build_pscube_cloud_sync.mjs` で配布用 `.gs` を生成する。`.gs` の共通パーサー部分を直接編集しない。

`node --test database_android/tool/test_pscube_cloud_sync.mjs` で、Driveの模擬実行・失敗からの復旧・既存Web読み込み・PythonのPC取り込み互換性を確認する。試験は既存 `check_before_build.sh` の `tool/test_*.mjs` による全試験の対象に含まれる。
